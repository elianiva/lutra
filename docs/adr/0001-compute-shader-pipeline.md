# Compute shader pipeline over render pipeline

The engine targets WebGPU compute shaders rather than a vertex+fragment render pipeline, even though a render pipeline is the more direct analog to the mobile app's Skia RuntimeEffect model.

**Why compute:** Grain is a priority — the mobile app's cheap per-pixel hash is not acceptable for the web engine, and proper film-grain (FBM noise with density weighting) benefits from workgroup shared memory. Real clarity (local contrast via multi-tap kernel) also needs shared memory for efficient neighbor access. Both are compute-native patterns. (In practice neither body ended up needing shared memory — texture loads are cached by the GPU, so direct neighbor sampling via textureLoad/textureSampleLevel sufficed.)

**Trade-off:** Compute shaders sample explicitly: `textureSampleLevel` with a requested LOD for filtered reads (`textureSample` is fragment-stage only — implicit derivatives — so compute passes must request a level), `textureLoad` for integer texel access and unfilterable formats (rgba32float LUT cubes). The dispatch model adds boilerplate (workgroup sizing, storage texture format negotiation). The upside is scatter writes, shared memory, and a cleaner path to future features (histograms, LUT tetrahedral interpolation).

**Considered alternative:** A render pipeline with a full-screen quad and fragment shader maps cleanly to the mobile `main(vec2 coord)` pattern, gives free bilinear filtering, and has less boilerplate. It was rejected because grain quality is a core requirement and compute unlocks it.

**Consequences:** Filtered reads go through `textureSampleLevel` on the binding-5 sampler — only on filterable formats, which is why passes ping-pong through rgba16float intermediates rather than rgba32float. `textureLoad` remains for integer texel access (LUT trilinear, passthrough/linearize) and unfilterable textures (rgba32float LUT cubes). The chain assembler emits a `@compute` entry point with `@builtin(global_invocation_id)` rather than a fragment shader. Chromatic aberration's source-texture sampling must be explicit.

**Multi-pass evolution (added 2026-07):** The original assembler merged every layer into a single compute pass per pixel. That made texture-sampling layers (chromatic aberration) sample the _source_ image instead of the accumulated result of earlier layers, and it forced sRGB-encoded texels into the linear pipeline. The assembler now emits one compute pass per layer; passes ping-pong through linear-light rgba16float intermediates and only the last pass encodes back to sRGB. A dedicated linearize pass is inserted ahead of the first sampling layer. Cost: N dispatches per frame instead of 1; benefit: correct chain semantics for any future neighbor-sampling body.

**Neighbor-sampling bodies (added 2026-07):** The multi-pass architecture now carries three neighbor-sampling bodies. Chromatic aberration samples its pass input at continuous radial offsets (bilinear `textureSampleLevel` on the binding-5 sampler) — R outward, B inward, full channel replacement, offset growing quadratically from the image center and expressed in UV space so the fringe stays proportional to the frame at any resolution. Clarity is local contrast — a 9-tap bilinear box blur (radius 4 px, `textureSampleLevel` with an explicit LOD; `textureSample` is fragment-stage only, so compute passes must request a level) of the pass input, then an unsharp-mask push away from the local mean, midtone-masked. Grain is 3-octave FBM over smooth value noise: an integer lattice hash (Wang-style, seeded with `u_frame` for per-frame animation) interpolated with quintic easing, replacing the mobile's per-pixel `fract(sin(dot(...)))` white noise. Grain has three Snapseed-style knobs (added 2026-07): `texture` (strength, amplitude ±0.15 linear at midtone), `size` (base noise cell, log 1.5→10 px), and `blur` (octave persistence 0.6→0.15; weights normalized by construction so blur changes character, not loudness). Sampling passes expose a binding-5 sampler; none of the bodies needed workgroup shared memory — direct texture loads were sufficient and validate cleanly (naga).

**Display path (added 2026-07):** Processing stays compute, but presentation is a second, trivial render pass — a fullscreen-triangle fragment shader that samples the compute output storage texture (bilinear, free) into the canvas swapchain. The frame never leaves the GPU on the display path; per-tick readback (copyTextureToBuffer + `mapAsync` + `createImageBitmap` + 2D `drawImage`) is gone, along with per-tick texture/buffer reallocation (resources are now image-scoped and reused). Readback survives only in the export path (`snapshot`). Renders are coalesced to one in flight (model `renderPending` + `queue.onSubmittedWorkDone`) so slider drags can't backlog the GPU queue.
