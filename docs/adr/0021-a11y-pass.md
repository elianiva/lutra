# A11y pass: focus-visible, red-on-dark contrast, valid tile HTML, favicon

Cheap, high-value accessibility fixes — targeted at what a keyboard +
screen-reader user hits immediately. Not a full audit.

**Status**: decided (2026-08-07 planning session); not yet implemented.

## Findings (verified)

1. **No focus-visible styles anywhere** — keyboard users cannot see where
   focus is (Tailwind v4 preflight adds no focus rings). The top a11y item.
2. **Red-on-dark contrast fails AA**: `--color-accent` (#cc0000) text on
   `--color-bg` (#111) ≈ **3.2:1** vs 4.5:1 required. The _fill_ red passes
   (white on #cc0000 ≈ 5.9:1).
3. **Nested interactive elements** in the gallery tile — the delete ✕ is a
   `button` inside the tile `button`: invalid HTML, breaks screen-reader
   semantics, can misfire on some browsers.
4. **No favicon** — blank page icon.

## Decisions

### D1 — Global focus-visible (CSS only)

```css
:focus-visible {
  outline: 1px solid var(--color-ink);
  outline-offset: 1px;
}
```

1px ink, not 2px accent: matches the hairline design language, reads on both
panels and image content (compare control, histogram float over the photo),
and avoids a red-on-red failure on the red-filled Save button.

### D2 — Two reds: fill vs text

New token `--color-accent-text` ≈ **#ff2a2a** (≈ 4.7:1 on #111 — passes AA)
for **red text on dark**: wordmark, "Save failed", error copy, export
filename. `--color-accent` (#cc0000) stays for **fills with white text**
(Save button, segmented active, slider thumbs) — brightening the fill would
drop white-on-red below 4.5:1 (white on #ff2a2a ≈ 4.0:1). Two tokens, two
roles; the rule lives in `styles.css`. Sweep: `text-accent` →
`text-accent-text` where it's text-on-dark (`top-bar.ts` wordmark + "Save
failed", `gallery/view.ts` "Open photo" outline button + notice bar; the LUT
picker selected border stays accent).

### D3 — Gallery tile restructure

The tile stays a `button`; the delete ✕ becomes a **sibling** absolutely
positioned over the tile's corner (wrapper is `relative`, ✕ gets a solid
`bg-panel/80` chip so it's legible on any thumbnail). Same visual placement,
valid HTML for everyone. This also unblocks the delete-confirm work
(docs/adr/0022), which touches the same spot.

### D4 — Favicon

`public/favicon.svg` — a hard-cornered red square (#cc0000, the brand) +
`<link rel="icon" type="image/svg+xml">` in `index.html`.

## Deferred (noted, not in this pass)

- Split-divider keyboard support (`role="separator"` + arrows) — the compare
  control offers a keyboard-reachable alternative, so it's not a blocker.
- `aria-pressed` on compare segments / export segmented rows.
- Skip link, landmarks audit (the two-route shell already has
  header/main/aside).

## Consequences

- CSS-only items verified visually (no unit tests); the tile restructure
  keeps all existing behavior — the `gallery/` suite runs unchanged.
