# RAW decode

**Status**: implemented (`packages/frontend/src/lib/decode-image.ts`, `raw-engine.ts`, `linear-image.ts`).

RAW files (CR2/CR3, NEF, ARW, RW2, ORF, RAF, DNG, and about 30 more) decode client-side at full resolution with [FlashRaw](https://flashraw.ybouane.com), a Rust decoder compiled to WebAssembly and installed from npm (`flashraw`). There is no owned build, no native toolchain and no committed binary: the npm package ships the wasm.

- **Decode lands as 16-bit sRGB** (`output: 'rgb16'`, `colorSpace: 'srgb'`, oriented by FlashRaw) and becomes two forms of one image. An 8-bit sRGB `ImageBitmap` is what the model, the thumbnails and the session identity read, as for every format. Linear half-float RGBA is registered against that bitmap (`gpu/linear-source.ts`, a `WeakMap`), and the GPU backend uploads it to an `rgba16float` texture as the chain's source, so the grade starts from sensor precision. The 8-bit texture still feeds the compare view's "before" half. The engine changes nothing: pass 0 reads linear light either way. `decodeImage` takes the longest edge the caller keeps (`longEdge`; the editor passes `PREVIEW_LONG_EDGE`, export and the tools pass none). The decode is then area-averaged to that size on the CPU in linear light, so the bitmap and the linear pixels both match the preview the GPU textures are sized to. A linear working space throughout the engine is still a future option; `rgb16` clips highlights at white, as the 8-bit path did.
- FlashRaw runs unpack, black/white normalization, as-shot white balance, demosaic, camera matrix and sRGB encode in one pass. In the page it runs in a Web Worker (`flashraw/worker`, pool of one) so the editor stays responsive; in the tools' image workers, which are workers already, it runs inline (`inlineEngine`). It is multithreaded when the page is cross-origin isolated and single-threaded otherwise. The app is isolated: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` come from `vite.config.ts` in dev and preview and from `public/_headers` in production. Any new cross-origin subresource must send CORS or `Cross-Origin-Resource-Policy` headers. The pool is created on demand, warmed when a file picker opens and terminated after 30 s idle, so the wasm heap does not live as long as the tab.
- Decode settings are deliberate: as-shot WB (the White balance layer adjusts relative to it — its range cannot fix a neutral decode under tungsten), full-size output unless the caller keeps less (see below), no exposure, black-point or white-point adjustment (don't fight the Exposure layer). The demosaic is bilinear; FlashRaw offers no other algorithm. With a `longEdge`, a sensor whose long edge is at least twice it uses FlashRaw's `half-size` demosaic (each 2×2 cell becomes one pixel): cheaper, and it still covers the target. Without a `longEdge` (export, tools) the decode is always full size.
- **The `RawEngine` seam** (`raw-engine.ts`) is what the app needs from a decoder: `withSession(blob, use)` opens a file, hands `use` a session (`size`, `srgb16(halfSize)`, `preview()`) and always closes it, and `warm()` starts the decoder early. `createImageDecoder(engine)` builds the decode functions over one engine; the app builds a single instance over `defaultRawEngine()` (pool in a window, inline in a worker) and tests build their own over a fake.
- Routing: one `decodeImage(blob, { bitmap?, longEdge? })` function. A `File` with a RAW extension, or any blob whose first bytes are not a browser format (JPEG, PNG, GIF, WebP, BMP, AVIF/HEIC; a saved Edit's source has no name, so bytes decide), tries FlashRaw first and falls back to `createImageBitmap`. Any other blob tries `createImageBitmap` first and falls back to FlashRaw. When both fail, the browser decoder's error is the one surfaced.
- Gallery tiles and `<img>` previews use the **embedded JPEG** (`rawPreview`, instant; `decodeThumbnailSource` and `displayUrl` fall back to the file or a full decode when there is none). LUT-bar thumbnails are cut from the editor's decoded source bitmap, never the embedded JPEG — embedded JPEGs carry the camera tone curve and would mismatch how the editor renders.
- Licensing: FlashRaw is MIT OR Apache-2.0. No copyleft component ships with the app.
- Nikon High Efficiency NEF (TicoRAW) is not decodable by any open decoder. It fails with `UnsupportedCompression` and takes the error path above.
- FlashRaw can also return the undemosaiced, normalized CFA (`output: 'normalized'`) and has a WebGPU backend, so a GPU demosaic stays possible without changing the service seam.
